# فحص المنصة كاملة (الفحص الآلي)

في فحصين بيشتغلوا لحالهم على GitHub مع كل تعديل (Pull Request) ومع كل دمج على `main`،
وممكن تشغّلهم بإيدك من تبويب **Actions ← Platform checks ← Run workflow**.

الفحصين ما بيلمسوا الموقع الحقيقي ولا بيانات الطلاب: بيشتغلوا على بيانات تجريبية وقاعدة بيانات مؤقتة.

## ١. الشاشات والمسارات (`npm run test:e2e`)
متصفح آلي بيفتح المنصة على كمبيوتر (1280px) وعلى موبايل (390px) وبيتأكد إنه:
- كل شاشة (الزائر، الطالب، المعلم، المدرسة، مدير المنصة) بتفتح بدون أخطاء وبدون تمرير أفقي.
- كل زر بالقائمة الجانبية بيضل بنفس الواجهة (مدير المدرسة ما بيطلع على واجهة المعلم).
- كل زر جوّا شاشات المدرسة بيضل جوّا واجهة المدرسة.
- مبدّل الجهات بيفتح الواجهة الصح، ومعلم المدرسة أو المركز ما بيشوف الاشتراك والفواتير.
- المسارات الأساسية: إنشاء مجموعة وإضافة طالب، إنشاء امتحان بمعاييره، تسليم الطالب من رابطه
  (ورمز خاطئ بينرفض، وأسماء الطلاب ما بتظهر)، اعتماد التصحيح، تصدير Moodle، مدير المنصة
  (الجهات الجديدة، المدفوعات)، دعوة معلم للمدرسة، تقارير الأهالي.

الملفات في `e2e/`. أول مرة على جهاز جديد: `npx playwright install chromium`.

## ٢. صلاحيات قاعدة البيانات (`npm run test:db`)
بيبني قاعدة البيانات كاملة على PostgreSQL مؤقت وبيشغّل `supabase/checks/rls_checks.sql`
(كل مستخدم بيشوف بيانات جهته بس، والطالب ما إله حساب، إلخ).
محلياً: `DATABASE_URL=postgres://... npm run test:db` على قاعدة فاضية. **ما تشغّله على Supabase الحقيقي.**

## لما تضيف شاشة جديدة
ضيف عنوانها في `e2e/helpers.ts` (بنفس ترتيب `src/routes.ts`) حتى تنفحص هي كمان.
