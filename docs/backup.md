# النسخ الاحتياطي

كل ليلة (00:30 UTC) يأخذ GitHub نسخة كاملة من المنصة:
- **قاعدة البيانات** كلها (الجهات، الطلاب، الامتحانات، الدرجات، الحسابات…).
- **الملفات المخزّنة**: صور أوراق الطلاب، إيصالات الدفع، شعارات الجهات.

الملفان مشفّران بكلمة سر قاعدة البيانات (`SUPABASE_DB_PASSWORD`)، ويُحفظان 14 يوماً.
مكانهما: Actions ← «Backup database» ← آخر تشغيل ناجح ← `platform-backup`.

**كل نسخة تُجرَّب تلقائياً قبل حفظها:** تُسترجع قاعدة البيانات في قاعدة فارغة وتُقارن أعداد
السجلات (الجهات، الطلاب، الأوراق، الدرجات، المستخدمين، الملفات) مع الأصل، ويُتأكد أن كل ملف
نُسخ. إذا اختلف أي شيء يفشل التشغيل ويظهر باللون الأحمر في Actions.

## الاسترجاع (لمبرمج، عند الحاجة فقط)

```bash
unzip platform-backup.zip
gpg --decrypt daqa-YYYY-MM-DD.dump.gpg  > daqa.dump    # يطلب كلمة سر قاعدة البيانات
gpg --decrypt files-YYYY-MM-DD.tar.gpg  > files.tar
# قاعدة البيانات: إلى قاعدة جديدة فارغة أولاً، للتأكد قبل أي استبدال:
pg_restore --no-owner --no-privileges -d "<رابط القاعدة الجديدة>" daqa.dump
# الملفات: tar -xf files.tar  ثم ارفع كل مجلد (submission-pages، payment-receipts، org-assets)
# إلى المخزن الذي يحمل نفس الاسم في Supabase، بنفس المسارات.
```

لا تسترجع فوق القاعدة الحقيقية مباشرة قبل موافقة صاحب المشروع.

## الحجم
نسخ GitHub تتسع لعدة مئات من الميغابايت. عندما تكبر صور الأوراق كثيراً (آلاف الأوراق شهرياً)
ننقل نسخة الملفات إلى تخزين خارجي رخيص، أو نجعلها تنسخ الجديد فقط.
